# 📚 학생정보통합관리시스템(ERP)

이 리포지토리는 우리가 함께 만들 서블릿/JSP 기반 학생 관리 ERP 프로젝트입니다.

원활한 협업과 나중에 발생할 수 있는 문제들을 미리 방지하기 위해 몇 가지 중요한 규칙과 안내 사항을 정했습니다. **프로젝트 시작 전에 모든 팀원이 꼭 한 번씩 꼼꼼하게 읽어주시길 바랍니다!**

## 🛠️ 개발 환경 통일

가장 중요합니다. "내 컴터에서는 왜 안되지..?" 라는 상황을 막기 위해, 아래 개발 환경을 **반드시 동일하게** 맞춰주세요.

* **IDE**: Eclipse ee
* **Project**: Dynamic Web Project
* **Java (JDK)**: **이건 추후에 상의**
* **WAS**: **`[서버: Apache Tomcat 10.1]`**
* **Encoding**: **UTF-8**
    * (이클립스 `Window > Preferences > General > Workspace`에서 `Text file encoding`을 `UTF-8`로 변경)

## 🚀 프로젝트 시작 가이드 (필수!)

**절대 이클립스에서 `New Project`를 하지 마세요!**

1.  **Git Clone**: 먼저 이 리포지토리를 각자 PC의 원하는 폴더(예: `C:\dev\`)로 `git clone` 받습니다.
2.  **Import**: 이클립스를 켜고 `File > Import... > General > Existing Projects into Workspace`를 선택합니다.
3.  **폴더 지정**: `Select root directory:`에서 방금 `clone` 받은 **프로젝트 폴더**(예: `C:\dev\servlet-student-erp`)를 선택합니다.
4.  **[주의!]** `Options`에서 **`Copy projects into workspace` 체크박스를 반드시 해제**해야 합니다. (체크하면 Git 연동이 꼬입니다.)
5.  **서버 설정**: 이클립스 `Servers` 탭에서 Tomcat 서버를 [개발 환경]과 동일한 버전으로 설정하고, 프로젝트를 서버에 추가(Add)합니다.
6.  **라이브러리**: 필요한 `.jar` 파일들은 **`WebContent/WEB-INF/lib`** 폴더에 이미 포함되어 있습니다. **절대 개인이 임의로 `.jar` 파일을 추가하거나 삭제하지 마세요.** (필요시 팀장과 상의)

## 🌿 Git 협업 규칙 (매우 중요!)

우리의 코드를 안전하게 관리하고, 서로의 작업이 꼬이지 않게 하기 위한 핵심 규칙입니다.

### 1. 브랜치 전략

* `main`: **(보호됨)** 최종 완성본이 올라가는 브랜치입니다. **절대 직접 Push 금지입니다.**
* `develop`: **(핵심)** 우리가 개발한 기능들이 합쳐지는 '개발용 메인' 브랜치입니다. **역시 직접 Push 금지입니다.**
* `feature/[기능이름]`: 각자 기능을 개발할 때 사용하는 브랜치입니다.
    * (예: `feature/login`, `feature/student-list`)

### 2. 작업 순서 (필수)

1.  **(작업 시작 전)** `git checkout develop` -> `git pull origin develop`
    * (항상 최신 `develop` 상태에서 작업을 시작합니다.)
2.  **(브랜치 생성)** `git checkout -b feature/[내기능]`
    * (본인이 맡은 기능 이름으로 새 브랜치를 만듭니다.)
3.  **(기능 개발)** 코드를 열심히 작성합니다.
4.  **(커밋)** `git add .` -> `git commit -m "[커밋종류] 상세 내용"`
    * (커밋 메시지 규칙은 아래를 참고해 주세요.)
5.  **(푸시)** `git push origin feature/[내기능]`
    * (본인의 feature 브랜치에만 푸시합니다.)
6.  **(PR 생성)** GitHub 홈페이지에서 `develop` 브랜치로 **Pull Request (PR)**을 생성합니다.
7.  **(코드 리뷰)** 코드를 확인하고 승인(Merge)하면 `develop` 브랜치에 합쳐집니다.

### 3. 커밋 메시지 규칙

커밋 내역을 쉽게 알아보기 위해, 메시지 앞에 말머리를 붙여주세요.

* `[Feat]`: 새로운 기능 추가 (예: `[Feat] 로그인 기능 구현`)
* `[Fix]`: 버그 수정 (예: `[Fix] 학생 목록 조회 시 500 에러 수정`)
* `[Refactor]`: 코드 리팩토링 (예: `[Refactor] StudentDAO 코드 효율화`)
* `[Docs]`: README.md 등 문서 수정

## 📦 패키지 구조 (역할 분담)

우리는 코드의 **'역할'**에 따라 패키지를 분리하는 **계층형 구조**를 사용합니다. **각 클래스가 자기 역할만 하도록** 꼭 지켜주세요.

* `controller`
    * **역할**: 서블릿(Servlet)만 위치합니다.
    * **하는 일**: 사용자의 웹 요청(request)을 받고, 응답(response)을 보냅니다. 실제 로직은 service에게 넘깁니다.
* `service`
    * **역할**: 핵심 기능(비즈니스 로직)을 처리합니다.
    * **하는 일**: 컨트롤러의 요청을 받아, DAO를 이용해 DB 데이터를 가져오거나 가공하는 등 '실제 기능'을 수행합니다.
* `dao`
    * **역할**: 데이터베이스(DB) 접속 전담입니다.
    * **하는 일**: 오직 SQL 쿼리문을 실행하고 DB에서 데이터를 가져오거나(SELECT), 넣거나(INSERT), 수정(UPDATE), 삭제(DELETE)하는 코드만 작성합니다.
* `dto`
    * **역할**: 데이터 운반용 객체 (Value Object)입니다.
    * **하는 일**: DB에서 가져온 학생 정보, 사용자가 입력한 회원가입 정보 등을 담는 '그릇'입니다. (주로 Getter/Setter로 구성)
* `common`
    * **역할**: 공통으로 사용되는 기능들입니다. (예: 학교에서 했던 DB 커넥션 관리 `JdbcConnectUtil.java`)
